# 卡组配置上线品质组件重制设计

## 目标

保留“四列卡库＋右侧详情与当前卡组＋固定底栏”的宏观结构，重做所有可见组件的内部构成与视觉资源，使卡组配置在 1152×648 下具备正式上线游戏界面的完整度、清晰度和一致性。

本次允许调整卡牌内部构成、面板承载、控件间距、字体层级、详情信息排布、卡组行项目和状态表现；不修改卡牌规则、数据模型、解锁逻辑、存档流程与宏观页面结构。

## 当前截图问题

- 卡牌只有华丽边框和文字，没有稳定卡面主体，呈现开发占位感。
- 文字直接浮在高细节背景上，卡库和列表缺少明确承载面。
- 金色雕花面积过大，边框、按钮和正文争抢注意力。
- 卡名、费用、阶段、数量与按钮没有稳定栅格，对齐关系弱。
- 右侧详情、当前卡组、费用曲线和验证状态缺少清晰分区。
- Hover、Selected、Disabled 和 Locked 的视觉差异不够明确。
- 筛选、排序、返回和底栏仍呈现默认程序控件质感。
- 部分九宫格资源在实际控件比例下被拉伸，装饰与正文区域互相侵占。

这些问题不能仅靠替换贴图解决，必须进行组件级重制。

## 原项目风格证据

- `assets/ui/generated/UI_Card.png`：暗色低饱和卡底、细铜边、局部花叶和干净内容区。
- `art_source/ui_components_preview.png`：圆角横向按钮、蓝绿与棕色面板、克制植物装饰。
- `tmp/main-menu-review/menu00000000.png`：夜间温室、蓝黑环境、暖金光源与向日葵主题。
- `tmp/battlefield-new-review.png`：低饱和蓝紫夜色、柔和中心亮度和安静背景密度。

采用“原有 UI 组件为主、温室氛围为辅”的轻量植物手册风：深蓝黑与灰蓝绿为大面积底色，暖白承载正文，氧化铜与柔金仅用于轮廓、焦点和状态反馈。

## 页面视觉架构

### 背景层

使用低细节夜间温室背景。卡库和右侧阅读区后方必须保持暗、静、低对比，不放置高亮植物、强窗格线或复杂透视焦点。增加柔和蓝灰雾层与暗角，使背景只负责氛围。

### 卡库承载层

四列卡库整体放在一块半透明深蓝绿收藏册面板上。面板使用轻微纸张或布纹、细铜边和少量角花，建立稳定阅读底色。筛选与排序位于面板顶端工具条，使用正式皮肤、统一高度和选中反馈。

### 右侧信息层

右侧划分为选中卡牌详情、当前卡组列表、费用曲线与规则反馈三个明确区域。三个区域使用同系列面板和一致内边距，通过间距和明度区分，不使用互相竞争的厚重边框。

## 卡牌组件

卡牌必须成为一个完整、稳定的组件，而不是边框上的散落文字。从上到下固定为：

1. 左上费用徽章。
2. 主视觉区：优先使用项目已有植物资源；缺少对应插画时使用统一植物纹章、叶片剪影或低对比植物标本图，禁止留空。
3. 卡名条：单行居中，超长名称使用受控字号或省略，不允许挤压其他信息。
4. 标签行：阶段与稀有度使用短标签或小徽记。
5. 数量与状态行：显示当前数量、携带上限或解锁费用。
6. 底部操作区：加入、已满、锁定等状态保持同一高度和位置。

普通、稀有、传奇共用相同轮廓、内边距和信息位置，仅改变窄边颜色、小型植物徽记与轻微光效：普通使用暗铜与灰绿，稀有使用冷青或低饱和蓝紫，传奇使用柔金向日葵徽记。

卡框在实际运行尺寸下保持一致比例；两行卡牌必须完整显示，滚动区域不得露出半张卡。

## 卡牌状态

- Normal：安静的细边和低对比底色。
- Hover：边线略亮、卡面轻微提亮，不改变尺寸。
- Selected：清晰但克制的柔金轮廓，并在详情区同步反馈。
- Disabled：降低饱和度，同时显示“卡组已满”或具体限制文字。
- Locked：主视觉压暗，显示锁图标和种子费用，仍可阅读卡名与基础属性。

状态不得只通过颜色表达，也不得改变卡牌布局、边框厚度或文字位置。

## 详情组件

详情区固定包含卡名与费用、稀有度/阶段/目标类型标签、主视觉或植物纹章缩略图、自然语言规则正文、当前数量与携带上限，以及一个明确的主操作按钮。详情面板必须具有稳定内边距，正文不得覆盖装饰，不得因背景插画导致对比不足。

## 当前卡组列表

每一行使用固定列布局：费用、卡名、数量、移除按钮。所有行保持统一高度，名称列弹性扩展，数量与按钮右对齐。Hover 和选中行提供轻微底色反馈。列表必须独立滚动，不允许文字直接浮在背景上，也不使用手工空格对齐。

## 费用曲线与规则反馈

费用曲线使用 1–8 费固定槽位的小型柱状图或刻度图，柱高表示数量，底部显示费用数字。空槽仍保留位置，避免数据变化时布局跳动。

规则反馈位于费用曲线下方：合法时显示克制的绿色或暖白提示；非法时显示警告图标和具体原因。不得只禁用保存按钮而不给原因。

## 顶栏、工具条与底栏

- 返回按钮、标题、种子和卡组数量按统一基线排列。
- 筛选和排序控件使用同系列紧凑皮肤，不保留默认 Godot 外观。
- 底栏次级操作使用统一尺寸与低对比样式。
- “保存卡组”是唯一主操作，使用项目既有主按钮语言和完整四态。
- 所有按钮中央必须有稳定文字安全区，不允许把完整插画直接压缩成按钮皮肤。

## 资源策略

重新规划 Manifest，不复用当前过度华丽且比例不适配的生成资源。新资源使用独立文件名，不覆盖旧资源；验证通过并完成 Godot 运行检查后再切换绑定。

资源至少包括低细节温室背景或压暗层；卡库、详情、卡组列表和工具条的轻量九宫格底板；三种品质卡框四态；卡面统一植物纹章或标本占位系列；费用徽章、锁、警告和移除图标；主按钮与次级按钮四态；费用曲线槽位与柱体。

生成资源必须以实际控件比例和用途为约束。九宫格只生成可安全拉伸的边框与平整中心；包含完整构图的插画不得作为九宫格。文字继续由 Godot 字体系统绘制。

## 实现边界

- 保持现有卡组模型、保存、解锁与筛选逻辑。
- 重构 `DeckCardView` 和 `DeckListItem` 的内部节点层级，使组件有明确固定区域。
- `DeckBuilder` 只负责页面状态与组件刷新，不继续拼接大量无名临时节点。
- 静态资源由 `scripts/art_manifest.gd` 按显式节点路径绑定；动态卡牌资源由组件根据稀有度和状态选择。
- 资源缺失时保留简洁、可读的程序化降级样式。

## 上线验收标准

### 自动验证

- Manifest `validate`、`plan`、`verify` 全部通过。
- 卡牌、列表、详情、费用曲线和页面交互测试通过。
- 测试覆盖四种卡牌状态、锁定状态、长卡名、不同费用分布和卡组非法状态。

### Godot 运行验收

必须从 Godot 实际运行生成 1152×648 截图，至少覆盖默认浏览、Hover 或 Selected、锁定卡牌、卡组已满或不可加入、非法卡组与保存禁用状态。

每张截图必须满足：

- 无空卡面、无开发占位感。
- 无文字悬浮、遮挡、裁切或压缩。
- 四列卡牌与两行完整显示，间距和基线一致。
- 背景不干扰正文，面板分区明确。
- 详情、列表、费用曲线和底栏具有清晰层级。
- 控件状态一眼可辨，且不只依赖颜色。
- 图片无拉伸变形，九宫格边角保持比例。
- 与原项目 UI 的配色、材质、线条和植物装饰语言一致。

任何一项不满足都必须返回相应阶段修正，不能以“功能可用”或“资源已生成”判定完成。

## 不在范围内

- 不修改卡牌数值、效果和稀有度规则。
- 不增加套牌命名、多套牌预设或分享功能。
- 不复制外部游戏美术或品牌资产。
- 不改变四列卡库与右侧栏的宏观结构。
