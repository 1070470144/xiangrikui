# 《最后的向日葵》Godot 原型设计规格

> 日期：2026-09-24  
> 状态：已确认方向，待实现  
> 引擎目标：Godot 4.x  
> 原型分辨率：1152×648（16:9）

## 1. 目标

制作一个可独立运行的 2D 防守游戏原型，验证《最后的向日葵》设计文档中的四个核心体验：

1. 守护位于环形花园中央的太阳母花；
2. 光脉既是植物供能网络，也是会被敌人破坏的生命线；
3. 敌人从四面进入，形成清晰但不混乱的包围压力；
4. 植物自动战斗，玩家通过布置与“太阳爆闪”主动救场。

原型使用可替换的程序绘制美术，优先还原既有美术规范中的冷暖对比、3/4 斜俯视感、厚涂剪影感和金色生命光脉。所有玩法对象保持独立场景或脚本边界，后续可直接替换为正式手绘资源。

## 2. 原型范围

### 必须实现

- 固定环形战场与中央太阳母花；
- 四条从母花延伸到外圈的光脉，每条包含一个可受击节点；
- 两种防御植物：近战范围型荆棘花、远程射击型棱镜花；
- 两种敌人：直扑母花的影兽、优先攻击光脉节点的蚀芽虫；
- 三个夜间波次，敌人从战场四边生成；
- 植物自动索敌、攻击、造成伤害并击杀敌人；
- 击杀敌人获得光能，母花也缓慢恢复少量光能；
- 主动技能“太阳爆闪”：消耗光能，对指定范围或母花周边造成范围伤害；
- 光脉节点受损、断裂、修复和断光状态；
- 白天准备阶段，可在限定槽位种植或调整植物；
- 母花生命值、光能、波次、阶段与技能状态 UI；
- 母花被摧毁后显示失败界面并可重新开始；
- 撑过第三波后显示胜利界面并可重新开始；
- 鼠标操作，以及数字键、空格、R 等键盘快捷键。

### 不在本次范围

- 随机地图、五区域战役、局外成长、祝福系统；
- 首领“太阳吞噬者”；
- 正式存档、设置菜单、Steam 功能；
- 配音、完整叙事演出和正式音频资源；
- 正式高清手绘资源与复杂骨骼动画。

## 3. 玩家流程

1. 游戏进入 12 秒白天准备阶段；
2. 玩家点击植物按钮，再点击可用种植槽进行布置；
3. 白天结束后进入夜晚，敌人按当前波次配置从四边出现；
4. 植物自动攻击，玩家观察光脉和敌人路径；
5. 击杀敌人获得光能；光能达到消耗要求时可释放太阳爆闪；
6. 夜晚敌人清空后返回短暂白天，允许补种和修复；
7. 完成第三波则胜利；母花生命归零则失败；
8. 结算界面按按钮或 R 键重新开始。

## 4. 战场与视觉

### 构图

- 中央 18% 范围为母花和核心根系；
- 内圈放置四条主要光脉；
- 中圈安排八个固定种植槽；
- 外圈为敌人移动区域和生成区；
- 画面边缘使用冷色雾、菌丝和破损温室剪影形成框景。

### 色彩

- 背景：深蓝黑 `#111827`、灰紫 `#25263A`；
- 土壤：暗棕紫 `#3A3032`；
- 植物：墨绿 `#263D35`、枯黄 `#A08A4A`；
- 生命光：金黄 `#E5B94B`、暖白 `#FFF0B0`；
- 技能：金橙 `#F59E45`；
- 敌人：黑紫 `#211C32`、冷青 `#4C8490`；
- 危险与腐化：暗红 `#8E3D4A`。

### 程序绘制策略

- 使用 Godot `CanvasItem._draw()` 绘制背景、花园环、光脉、单位主体和 UI 装饰；
- 使用多层椭圆、多边形、曲线和半透明光晕模拟厚涂剪影与纸张层次；
- 使用缓慢呼吸、轻摆、光流粒子和短促受击闪烁增强生命感；
- 不依赖外部纹理即可运行，正式资源可通过 Sprite2D 节点逐项替换。

## 5. 核心规则

### 太阳母花

- 初始生命：300；
- 被影兽攻击时扣血；
- 随生命下降逐步降低亮度、花瓣张开幅度和饱和度；
- 生命归零立即停止生成与战斗，进入失败状态。

### 光脉节点

- 四个节点，各自连接母花与一组种植槽；
- 初始生命：100；
- 蚀芽虫优先选择存活节点；
- 节点生命归零后对应光脉断裂；
- 断光植物保留轮廓但停止攻击，并显示冷紫腐化状态；
- 白天点击受损或断裂节点可消耗光能修复。

### 植物

- 荆棘花：较短攻击范围，周期性对范围内所有敌人造成伤害；
- 棱镜花：较长攻击范围，锁定最近敌人并发射可见光弹；
- 植物只有其所属光脉节点存活时才工作；
- 种植消耗白天资源“种子”，每个准备阶段补充固定数量。

### 敌人

- 影兽：中速，优先移动至母花并持续攻击；
- 蚀芽虫：更快、生命较低，优先攻击最近的存活光脉节点；
- 敌人通过简单转向移动，不使用复杂导航网格；
- 进入攻击距离后停止移动并按间隔造成伤害；
- 死亡时化为冷色烟尘，并向光能计量注入金色粒子。

### 太阳爆闪

- 默认消耗 40 光能；
- 默认以鼠标位置为中心，作用半径约 150 像素；
- 对范围内所有敌人造成高额伤害，并显示扩散金色光环；
- 光能不足时按钮和准星给出明确的暗化反馈；
- 空格键进入或直接触发技能瞄准，鼠标左键确认，右键或 Esc 取消。

## 6. 波次与难度

原型使用三波固定配置，保证每一波引入一个新的理解重点：

- 第 1 波：仅影兽，教学中央防守；
- 第 2 波：加入蚀芽虫，教学光脉保护与断光；
- 第 3 波：数量与方向同时增加，要求使用太阳爆闪救场。

生成方向使用可读的边缘预警标记。敌人不会直接出现在植物旁边；每个入口在生成前短暂显示冷青或暗红脉冲。

## 7. 软件结构

### 场景

- `Main.tscn`：游戏根场景、状态协调、相机和 UI；
- `Battlefield.tscn`：战场绘制、槽位、光脉与生成点；
- `MotherFlower.tscn`：母花状态、受击和绘制；
- `LightNode.tscn`：光脉节点状态、修复和断裂信号；
- `Plant.tscn`：植物基类场景，通过配置区分荆棘花和棱镜花；
- `Enemy.tscn`：敌人基类场景，通过配置区分影兽和蚀芽虫；
- `Projectile.tscn`：棱镜花弹道；
- `HUD.tscn`：状态栏、植物栏、技能按钮和结算层。

### 脚本职责

- `game.gd`：阶段机、资源、波次、胜负和重新开始；
- `battlefield.gd`：位置定义、种植交互、生成方向提示；
- `mother_flower.gd`：核心生命与视觉状态；
- `light_node.gd`：节点生命、连接状态和修复；
- `plant.gd`：索敌、冷却、攻击与断光响应；
- `enemy.gd`：目标选择、移动、攻击、受伤与死亡；
- `projectile.gd`：命中和视觉轨迹；
- `hud.gd`：只负责显示与输入转发，不包含战斗规则。

对象通过 Godot 信号沟通：`damaged`、`destroyed`、`enemy_died`、`wave_cleared`、`plant_requested`、`sunburst_requested`。游戏根节点保存唯一的阶段与资源真值。

## 8. 输入

- 鼠标左键：选择按钮、种植、修复、确认技能；
- 鼠标右键 / Esc：取消当前放置或技能；
- `1`：选择荆棘花；
- `2`：选择棱镜花；
- `Space`：选择太阳爆闪；
- `R`：在结算界面重新开始；
- `Enter`：跳过剩余白天倒计时并开始下一波。

## 9. 错误与边界处理

- 不允许在已占用槽位重复种植；
- 种子不足、光能不足或阶段不允许时不执行操作，并显示短暂提示；
- 敌人目标被提前摧毁时立即重新选择有效目标；
- 所有敌人被消灭后只触发一次波次结束；
- 失败或胜利后冻结战斗逻辑，但保留 UI 输入；
- 节点修复后，其所属植物恢复工作；
- 游戏重开会清理所有动态节点、计时器和旧信号连接。

## 10. 验证方法

### 自动检查

- Godot 无窗口启动能够导入并解析全部场景与脚本；
- 主场景能运行固定时长且无脚本错误；
- 测试脚本覆盖伤害、死亡、光能奖励、断光、修复和波次状态转换；
- 搜索工程确认不存在未解析资源路径或明显占位标记。

### 手动验收

- 30 秒内能理解保护中央母花；
- 光脉正常、受损和断裂状态能一眼区分；
- 玩家能通过鼠标完成种植、修复和太阳爆闪；
- 四面来敌有方向预警，不出现不可理解的偷袭；
- 第三波需要主动技能但不会形成必败局；
- 胜利、失败和重新开始均可完整走通；
- 画面最亮区域始终属于母花、光脉或太阳技能。

## 11. 完成定义

满足以下条件才算原型完成：

1. 工程可由 Godot 4 打开并运行；
2. 三波流程、胜利、失败、重开均可操作；
3. 光脉断裂确实会停用对应植物，修复后恢复；
4. 两种植物与两种敌人的行为可辨认；
5. 太阳爆闪由玩家主动触发并消耗光能；
6. UI 能持续准确反映生命、光能、波次与阶段；
7. 无解析错误、崩溃或阻塞流程的已知问题；
8. 视觉风格符合既有美术规范的冷暗环境与温暖生命光对比。
