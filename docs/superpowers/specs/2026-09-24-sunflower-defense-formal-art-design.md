# 《最后的向日葵》正式美术替换规格

> 日期：2026-09-24  
> 状态：方向已确认，待资源制作与接入  
> 目标引擎：Godot 4.7.2  
> 基础画面：1152×648

## 1. 目标

将当前依赖 GDScript 几何绘制的交互原型升级为具有统一商业展示品质的“末日温室厚涂绘本风”版本。保留现有玩法、碰撞、数值和交互逻辑，只替换或增强视觉呈现。

最终画面必须同时表达：

- 冷暗、衰败、被腐化阴影吞噬的末日温室；
- 中央太阳母花与金色光脉仍然温暖、有生命力；
- 植物、敌人和可交互光脉在实际战斗尺寸下轮廓清楚；
- 美术资源、动态光效与 UI 属于同一视觉体系，不再呈现几何原型感。

## 2. 美术方向

### 核心风格

- 3/4 斜俯视高清手绘；
- 厚涂绘本质感，可见柔和笔触与纸张颗粒；
- 真实植物结构经过功能性夸张；
- 敌人为被蓝紫阴影侵蚀的生物，而非纯黑剪影；
- 冷色环境与暖色生命光形成稳定的明度和色温对比；
- 不使用像素画、扁平矢量图标风、糖果色或赛博霓虹。

### 统一色板

- 深夜背景：`#111827`
- 远景阴影：`#25263A`
- 土壤与石材：`#3A3032`
- 普通叶片：`#263D35`
- 枯萎植物：`#69705A`、`#A08A4A`
- 生命光脉：`#E5B94B`

## 4. 生成与后期规则

- 所有独立单位必须使用纯透明背景，不使用棋盘格、白底、阴影方框或文字；
- 同类状态图必须共享画布尺寸、接地点、轮廓比例和摄像机角度；
- 透明边缘进行去白边和去黑边处理；
- 缩小到游戏实际尺寸后检查轮廓，不以原始大图细节作为验收依据；
- 资源不包含文字、UI 标签、光标、边框或未经要求的环境物件；
- 角色自带柔和接地阴影，但不烘焙大范围光晕；
- 发光主体保留局部绘制高光，范围光、脉冲和 Bloom 由 Godot 动态叠加；
- 所有 PNG 使用 sRGB，保留 Alpha，关键单位不进行有损压缩。

## 5. Godot 接入结构

### 文件目录

```text
assets/
├── backgrounds/
├── core/
├── plants/
├── enemies/
├── nodes/
├── effects/
└── ui/
```

### 运行时策略

- 背景由 `battlefield.gd` 加载底图与前景雾，程序绘制仅保留动态光脉、种植槽、预警和瞄准反馈；
- 母花、植物、敌人和光脉节点在现有 Node2D 下增加 Sprite2D；
- 脚本根据生命、种类和供能状态切换纹理，不改变公共玩法 API；
- 所有 Sprite2D 按统一接地点定位，脚本负责呼吸、摆动、受击闪白、轻微缩放和状态过渡；
- 正式贴图加载失败时允许回退到当前程序绘制，以避免场景完全不可运行；
- UI 使用 StyleBoxTexture 与 AtlasTexture 接入，保留当前按钮和标签节点，避免重写交互逻辑；
- 光脉线、太阳爆闪范围、生成预警和选中反馈保留实时绘制，确保玩法状态准确。

## 6. 动画与反馈

- 母花：健康呼吸、受击短闪、生命阶段交叉淡入；
- 植物：2%—4% 幅度轻摆；攻击时短促压缩与回弹；
- 影兽：移动时前后压缩，攻击时前扑；
- 蚀芽虫：身体分节轻微摆动，攻击时头部快速前伸；
- 光脉节点：健康状态缓慢亮度呼吸，受损状态不规则闪烁；
- 死亡：敌人主体快速淡出并叠加消散贴图；
- 太阳爆闪：0.4 秒扩散、旋转和淡出，峰值亮度不能遮挡母花轮廓超过 0.15 秒。

## 7. 实施顺序

1. 制作并接入战场背景与前景雾，先建立整体画面基准；
2. 制作母花三状态，校准所有单位的视觉比例；
3. 制作两种植物和光脉节点状态；
4. 制作两种敌人并确认实际战斗尺寸的轮廓差异；
5. 制作光弹、太阳爆闪和消散特效；
6. 制作 UI 面板、按钮和图标；
7. 统一导入参数、接地点、层级、色彩与运行时动画；
8. 生成新截图，与当前程序绘制版本进行替换前后对比。

## 8. 验收标准

- 运行画面中母花、植物、敌人和节点均使用正式 PNG，而非几何主体；
- 背景和前景形成末日温室空间层次，同时不干扰玩法识别；
- 两种植物、两种敌人在 100% 游戏缩放下可凭轮廓区分；
- 健康、断光、受损和断裂状态无需文字即可理解；
- 敌人不会融入背景，金色光脉不会被 UI 或场景高光抢夺；
- UI 面板、按钮和图标与场景材质及色板一致；
- 所有既有单元测试、交互测试和 900 帧运行检查继续通过；
- Godot 导入日志没有缺失资源、解析错误或透明贴图加载失败；
- 最终截图相比原型截图不再呈现几何占位感，并符合既有美术风格规范。

## 9. 完成定义

只有当资产清单中的正式资源全部生成、后期整理、放入 `assets/`、接入对应运行时对象，并通过视觉与功能验证后，正式美术替换才视为完成。
