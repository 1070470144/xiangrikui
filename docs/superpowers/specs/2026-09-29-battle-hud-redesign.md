# 战斗 HUD 结构优化设计

日期：2026-09-29  
范围：`scripts/hud.gd`、`tests/test_battle_hud.gd`、`art_source/manifests/battle_hud.json` 及战斗 HUD 专用生成资源  
目标平台：Windows / Steam，16:9，最低验收分辨率 1152×648

## 1. 功能定位

战斗 HUD 是玩家在白昼部署和夜间防守时的唯一常驻操作层。优化目标不是增加新系统，而是在不改变战斗规则、快捷键和数据来源的前提下，降低遮挡、强化昼夜阶段差异，并让生命、资源、威胁与当前可执行操作按优先级被读取。

成功标准：

- 战场中央和母花主体不被常驻 HUD 遮挡；
- 玩家能在一秒内读取母花生命、当前阶段、光能和最重要的阶段操作；
- 白昼只突出部署、修复和开始守夜，夜晚只突出手牌、威胁和太阳爆闪；
- 1152×648、1280×720、1920×1080 下所有常驻控件均在视口内且互不重叠；
- 现有 `Game` 到 HUD 的状态字典、信号和快捷键契约保持兼容。

## 2. 现状问题

当前截图 `output/imagegen/previews/hud-day-runtime.png` 与 `hud-night-runtime.png` 显示：

- 顶部中央阶段面板与常驻通知条叠成大块，过多侵入战场；
- 夜间网络雷达和威胁雷达分占左右下角，形成两个同等级视觉中心；
- 底部卡牌的图标、名称和费用关系不一致，夜间手牌外框为四张卡保留了过宽空间；
- 左下“当前选择”在没有具体选中对象时仍常驻，占用低价值空间；
- “开始守夜”和“太阳爆闪”虽是阶段主操作，但与卡牌带的层级、对齐和反馈不统一；
- 大面积纯色面板削弱了背景和中央母花作为视觉锚点的作用。

## 3. 商业案例调研与适配

### 3.1 Thronefall

来源：[Steam 商店与官方截图](https://store.steampowered.com/app/2239150/Thronefall/)

采用项：低遮挡、阶段相关操作集中、非当前功能及时退场。适配为昼夜共用同一条底部操作带，随阶段切换内容。  
不采用项：其扁平、极简、低纹理视觉语言与本项目厚涂末日温室风不一致。

### 3.2 They Are Billions

来源：[Steam 商店与官方截图](https://store.steampowered.com/app/644930/They_Are_Billions/)

采用项：资源与阶段信息使用稳定锚点，警报临时覆盖普通状态，建造操作形成明确工具带。适配为左上生命、顶部阶段、右上资源和底部操作的固定阅读路径。  
不采用项：不复制密集 RTS 工具栏、蒸汽朋克材质和多行微型数值。

## 4. 原项目风格证据与约束

依据 `Design/Sunflower-Defense-Art-Style-Guide.md`、现有主菜单、卡组编辑器和 HUD 资源：

- UI 方向为“旧园艺记录册 + 发光仪器”；
- 面板使用深蓝黑或深棕紫半透明底，避免纯黑；
- 常规边框使用磨损旧黄铜细线，生命与可用状态使用金黄、暖白；
- 冷紫与暗红只用于腐化、危险、首领和不可用反馈；
- 中文正文保持清晰无衬线，标题可使用较强字重，不生成烘焙文字；
- 装饰必须让位于数值、状态和战场轮廓；
- 新生成资源继承厚涂绘本、轻纸张纹理、旧黄铜和植物根脉装饰，不使用科技霓虹或外部案例美术风格。

## 5. 选定布局：收边式昼夜双态 HUD

### 5.1 稳定锚点

- 左上：`MotherStatusPanel`，紧凑展示母花头像、生命条、生命数值和光脉状态。
- 顶部中央：`PhaseBanner`，使用窄型两层结构。主层显示“第 N 夜 / 白昼或夜战”，副层按阶段显示倒计时、守夜进度、剩余敌人或首领状态。
- 右上：`ResourcePanel`，横向展示光能与种子。资源不足只影响对应数值与相关操作，不改变整个面板颜色。
- 右侧中上：统一的 `TacticalInstrumentFrame`。白昼显示光脉网络；夜晚在同一圆盘中显示网络内圈和威胁方向外圈。
- 底部中央：`PhaseActionTray`，白昼承载部署卡和修复，夜晚原位承载四张战斗手牌。
- 右下：`PrimaryActionButton`，白昼绑定开始守夜，夜晚绑定太阳爆闪。名称可保留兼容节点或提供别名节点供既有测试和绑定查找。

### 5.2 按需层

- `SelectionDetailPanel` 仅在具体植物、光脉节点、敌人或可部署项被选中时出现；默认隐藏。
- `NotificationBanner` 只在事件触发时从阶段栏下方短暂出现，到时淡出；不再作为常驻占位。
- 母花强化选择、胜负结果等模态层保持全屏阻断输入，其内部卡牌不在本次结构重排范围内。

### 5.3 白昼状态

- 显示部署卡、修复、网络仪表和开始守夜；
- 隐藏夜间手牌、威胁外圈和太阳爆闪；
- 倒计时进入最后 15 秒时，阶段副层与开始守夜按钮出现低频暗红脉冲，但不遮挡战场；
- 当前选择通过金色描边、轻微抬升和详情面板同时反馈。

### 5.4 夜晚状态

- 底部托盘原位切换为四张手牌，宽度按实际卡数收缩；
- 战术仪表保留网络内圈，并增加八方向威胁外圈、首领标记和强弱层级；
- 太阳爆闪显示真实费用。能量不足时图标和边框降亮，费用转暗红，按钮禁用；
- 剩余敌人、波次进度和首领状态只出现在阶段副层，不另建大面板。

## 6. 组件边界与数据流

`Game.get_hud_battle_state()` 继续提供结构化战斗状态；HUD 不直接读取或修改战斗对象。`update_battle_state()` 负责公共数值和阶段切换，`update_network_radar()` 与 `update_threat_compass()` 继续独立接收各自快照，再由统一战术仪表组合显示。

组件拆分：

- 状态组件：母花生命、阶段、资源；
- 操作组件：阶段托盘、部署卡、战斗手牌、主操作；
- 战术组件：网络内圈、威胁外圈；
- 临时反馈：选择详情、通知、模态层。

现有信号 `plant_requested`、`repair_requested`、`wave_requested`、`sunburst_requested`、`combat_card_requested`、`radar_focus_requested` 等保持不变。资源贴图加载失败时回退到可读的 `StyleBoxFlat` 临时 UI，功能不得失效。

## 7. Manifest 与资源计划边界

阶段 2 更新 `art_source/manifests/battle_hud.json`，完整记录文本、面板、按钮、图标、交互状态和显式节点绑定。预计需要生成的资源类别为：

- 阶段主操作按钮四态九宫格；
- 昼夜共用操作托盘九宫格；
- 紧凑状态面板边框；
- 统一战术仪表外框与威胁刻度装饰；
- 开始守夜与太阳爆闪使用的独立图标（不共用同一语义图标）。

文字、数值、倒计时、费用和方向字母均由 Godot 渲染，不进入图片。实际生成批次必须在 Manifest 校验、功能测试和临时 UI 运行通过后另行向用户确认；未经确认不得调用 `mm-api/gpt-image-2`。

## 8. 测试与验收

自动测试至少覆盖：

- 必需节点、信号与公开更新方法仍存在；
- 昼夜状态只展示相关操作；
- 四张手牌时托盘按内容收缩；
- 选择详情默认隐藏并能按状态显示；
- 通知为临时状态，不永久占位；
- 战术仪表在昼夜切换时更新正确的网络与威胁层；
- 资源不足会禁用主操作并提供可读反馈；
- 三档目标分辨率下控件在视口内、无重叠、底部操作不遮挡中央母花。

运行验收需要保存白昼、普通夜战、首领夜战、资源不足、选中对象和通知出现六种关键状态截图。阶段 4 将这些截图与本设计、原项目风格、案例采用项和 Manifest 逐条比较，任何未处理差异都必须返回对应阶段修正。

## 9. 非目标

- 不修改战斗数值、卡牌效果、波次规则或镜头控制；
- 不重做母花强化选择和胜负结果面板；
- 不复制外部游戏的品牌、美术资产或具体皮肤；
- 不覆盖现有用户资源；冲突时使用新的稳定资源名并更新 Manifest。
