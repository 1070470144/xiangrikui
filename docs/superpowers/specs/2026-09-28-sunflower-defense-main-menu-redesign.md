# 《最后的向日葵》主菜单重设计规格

> 日期：2026-09-28  
> 状态：设计已确认  
> 目标引擎：Godot 4.7.2  
> 基础画面：1152×648

## 1. 目标与范围

将当前左右等分、账号信息占据大量首屏空间的主菜单，重构为符合项目既有“末日温室绘本风”的沉浸式入口。新版主菜单必须让玩家首先感受到“末代园丁进入废弃温室、守护最后太阳”，其次才是账号、统计和设置功能。

本次包含：

- 新的主菜单背景与首屏布局；
- 精简账号入口和账号管理浮层；
- 七夜记录页；
- 图鉴与设置页的统一视觉整理；
- 主菜单按钮状态、键盘焦点和页面过渡；
- 相关自动化测试、运行截图和视觉验收。

本次不改变：

- 固定七夜关卡的玩法、数值和战斗场景；
- 本地账号与存档文件格式；
- 当前单战役 `start_requested` 信号和开始游戏的主流程；
- 已删除的无限模式，不在本次恢复；
- 现有植物、敌人和战斗 UI 资产。

## 2. 设计依据

新版主菜单遵循 `Design/Sunflower-Defense-Art-Style-Guide.md` 与 `Design/Sunflower-Defense-GDD.md`：

- 核心风格为“末日温室绘本风”；
- UI 语言为“旧园艺记录册 + 发光仪器”；
- 环境使用冷蓝紫、深棕紫和低饱和墨绿；
- 生命、选中和主要操作使用金黄与暖白；
- 太阳母花必须是画面最暖、最亮的视觉锚点；
- 不使用现代科技 HUD、霓虹赛博、过度玻璃拟态、扁平卡通或繁复中世纪花纹。

## 3. 首屏构图

### 3.1 背景与主视觉

- 使用一张全屏 16:9 废弃温室夜景作为背景。
- 温室骨架、破碎玻璃、枯萎植物和冷雾集中在画面边缘，形成框景。
- 太阳母花位于偏左中心，周围只有克制的金色根脉、暖光和少量微粒。
- 右侧约 36% 保持低细节、低对比，为菜单面板提供稳定阅读区域。
- 背景本身不包含文字、按钮、边框、图标、人物或水印。

### 3.2 标题与文案

- 标题“最后的向日葵”位于母花上方或左上方。
- 标题使用项目可用的清晰中文字体，搭配少量古典气质；不得以难读的装饰字体牺牲可读性。
- 副文案固定为：“太阳已经熄灭，而守夜仍将继续。”
- 标题和副文案不能遮挡母花主体轮廓。

### 3.3 菜单层级

- 菜单为右侧窄长的旧园艺记录册面板，建议宽度 330–360 px。
- 面板使用深蓝灰或深棕紫半透明底、细金色植物学边框、轻微纸张与氧化金属质感。
- 有存档时主按钮文案为“继续守夜”，无存档时为“开始守夜”。
- 主按钮下方显示一行存档摘要，例如“第 3 夜 · 酸雨将至”。
- 次级操作依次为“七夜记录”“温室图鉴”“设置”。
- “退出游戏”为面板底部的低强调文字按钮，不与主按钮同级。
- 版本信息移动到左下角并降低对比度。

### 3.4 账号入口

- 账号信息不再常驻占据左侧大卡片。
- 右上角显示小型园丁铭牌，仅包含头像符号、玩家名称和“本地存档”状态。
- 点击铭牌打开账号管理浮层。

## 4. 页面与组件

### 4.1 账号管理浮层

账号浮层保留并整理现有功能：

- 当前账号名称与本地存档说明；
- 七夜进度、最高夜晚和游戏时间；
- 本地账号列表；
- 切换账号；
- 新建账号与名称校验；
- 返回主菜单。

现有 `user://local_profile.cfg` 和 `user://local_accounts.cfg` 数据结构保持不变。

### 4.2 七夜记录

- 使用横向七节点展示固定关卡进度，不提供关卡选择或跳关。
- 已通过夜晚使用稳定金色光点。
- 当前夜晚使用暖白呼吸光。
- 未解锁夜晚使用灰紫枯萎节点。
- 特殊夜晚显示简短名称，包括“酸雨”“雷雨”“根冠巨像”和最终夜。
- 页面只读取现有存档数据，不引入新的长期成长系统。

### 4.3 温室图鉴

- 保留植物和怪物两个分类及现有正式贴图。
- 使用居中的园艺记录册面板和统一金色分隔线。
- 卡片在 1152×648 下不得裁切说明文字或返回按钮。

### 4.4 设置

- 保留主音量和全屏显示。
- 使用与其他子页面一致的居中记录册面板。
- 设置立即生效，仍只作用于当前设备。

### 4.5 子页面通用行为

- 子页面打开时，主背景继续可见，并覆盖约 55% 的深色遮罩。
- 返回按钮位于面板左上角；`Esc` 可返回上一层。
- 页面切换不重建或改写本地存档。

## 5. 交互与动效

### 5.1 按钮状态

- 默认：深墨绿或深棕紫底、细金边、暖白文字。
- 悬停：边框亮度增强，并出现一次弱金色根脉掠光。
- 按下：背景略暗、金边收紧；不改变控件尺寸和布局。
- 禁用：降低亮度和饱和度，同时保持文字可读。
- 键盘焦点：显示清晰的金色外框，支持方向键与 `Enter`。
- 所有主要点击区域高度不低于 48 px。

### 5.2 环境动效

- 母花以约 3 秒周期进行轻微亮度呼吸。
- 冷雾和金色微粒缓慢移动，不能干扰菜单阅读。
- 标题以约 300 ms 淡入并轻微上移。
- 菜单项依次淡入，间隔约 50 ms。
- 减少动态效果模式下关闭位移、根脉掠光和连续粒子，只保留短淡入。

### 5.3 开始游戏过渡

点击主按钮后：

1. 菜单和文字快速淡出；
2. 母花暖光短暂增强；
3. 暗色从四周收拢；
4. 进入固定七夜战场。

总时长控制在 450–600 ms。自动化测试和无图形验证可以跳过过渡，避免测试依赖动画时序。

## 6. 图片生成方案

### 6.1 生成管线

- 复用项目已有 `sprite-gen` OpenAI 图片生成管线，不新建重复客户端。
- 使用用户指定的 OpenAI 兼容 Base URL：`https://newapi.oairegbox.cc/`。
- 模型固定为 `gpt-image-2`。
- 使用兼容的 `/v1/images/generations` 请求路径。
- API Key 仅从环境变量读取，不写入仓库、脚本、报告或日志。
- 图片调用属于按次计费操作，必须显式指定 OpenAI provider，不设置为自动回退目标。

### 6.2 生成要求

- 生成 16:9 主菜单背景，优先使用管线支持的原生 16:9 尺寸，再处理为 1152×648。
- 风格为高质量厚涂绘本、真实植物学结构、轻微纸张纹理。
- 场景为太阳熄灭后的废弃维多利亚温室内部。
- 画面主体为偏左中心的健康太阳母花；右侧留出低细节菜单空间。
- 色板遵循项目规范：`#111827`、`#25263A`、`#3A3032`、`#263D35`、`#E5B94B`、`#FFF0B0`。
- 禁止生成 UI、文字、字母、数字、标签、人物、Logo 和水印。

### 6.3 资产处理与落盘

- 保存完整提示词和生成报告到 `art_source/`。
- 检查主体位置、菜单留白、错误文字、水印和风格一致性。
- 裁切或缩放到严格 1152×648，输出无损 PNG。
- 新背景放入 `assets/backgrounds/`，由 `scripts/art_library.gd` 统一引用。
- 如果首次生成不满足构图或禁用项，调整提示词后重新生成，不通过绘制 UI 遮盖生成缺陷。

## 7. 工程结构

- 继续由 `scripts/main_menu.gd` 管理主菜单页面，但将背景、首屏、账号、七夜记录、图鉴和设置拆为职责明确的构建函数。
- 如共享样式或动画逻辑明显增长，可提取一个仅服务主菜单的辅助脚本；不进行无关重构。
- 保留 `start_requested` 信号和 `main.gd` 的单战役换屏逻辑。
- 主按钮继续直接启动固定七夜关卡，不重新引入模式参数。
- 正式背景加载失败时允许回退到现有背景或安全纯色，使主菜单仍可操作。
- 控件使用锚点、容器和最小尺寸适配 1152×648，不依赖空格或固定文本填充定位。

## 8. 错误处理

- 图片生成缺少 API Key、接口拒绝、响应缺图或 PNG 校验失败时立即停止，不自动切换其他付费提供方。
- 生成失败不得覆盖现有背景资源。
- 本地账号创建失败时保持当前页面与输入内容，并提供可读的校验反馈。
- 背景、母花或 UI 纹理缺失时使用安全的 Godot 样式回退，不让场景崩溃。
- 页面切换期间忽略重复点击主按钮，避免重复发出开始信号。

## 9. 验证与验收

### 9.1 自动化验证

- 现有主菜单契约、账号和游戏流程测试继续通过。
- 新增或扩展测试以覆盖：
  - 主按钮存在并直接启动 `level`；
  - 账号入口、七夜记录、图鉴和设置可以打开与返回；
  - `Esc` 返回行为；
  - 键盘焦点顺序；
  - 1152×648 下关键按钮和账号入口不被裁切；
  - 无背景纹理时的安全回退。

### 9.2 视觉验证

- 使用 Godot 正常渲染器生成新版主菜单截图。
- 与重设计前基准图 `menu_baseline00000002.png` 对照。
- 检查太阳母花是否为最亮、最暖和最先被注意的区域。
- 检查右侧菜单是否清晰但不过度压暗或切割背景。
- 检查所有文字、焦点、按钮状态和子页面是否可读且无裁切。
- 检查背景没有错误文字、水印、生成式 UI 或与项目冲突的赛博元素。

### 9.3 完成定义

只有当以下条件全部满足，本次主菜单重设计才视为完成：

1. 新背景由指定兼容接口与 `gpt-image-2` 生成并通过视觉检查；
2. 推荐的温室入口式首屏已经接入 Godot；
3. 账号资料收进右上角入口和账号管理浮层；
4. 七夜记录、图鉴和设置页可正常使用；
5. 主菜单交互、键盘焦点和返回行为可用；
6. 自动化测试、Godot 启动检查和新版运行截图验证通过；
7. 未改变固定七夜玩法与现有本地存档契约。
