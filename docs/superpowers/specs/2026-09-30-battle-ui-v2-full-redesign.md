# 战斗界面 UI V2 全量重做设计

日期：2026-09-30  
范围：昼夜战斗 HUD、母花强化、暂停、胜利与失败界面  
目标平台：Windows / Steam，16:9  
视觉生成：`gpt-image-2`，模块化透明 PNG 资源

## 1. 目标与边界

本次工作删除并替换现有战斗界面的全部视觉资源与布局，但保留战斗玩法、数据来源、公开接口、信号和快捷键。新界面延续“末日温室 + 旧园艺手册 + 黄铜发光仪器”的项目风格，并采用边缘化、低遮挡的信息布局。

重做范围包括：

- 白昼部署 HUD；
- 夜间战斗 HUD；
- 母花强化选择；
- 暂停界面；
- 胜利结算；
- 失败结算；
- 通知、选择详情、资源不足、首领威胁等临时状态。

不修改战斗数值、卡牌效果、波次规则、存档格式、镜头规则或关卡内容。主菜单、卡组编辑器与战场美术不在本次范围内。

## 2. 成功标准

- 中央战场和母花主体保持清晰，不被常驻 UI 长期遮挡；
- 玩家能快速读取母花生命、当前阶段、资源、威胁和当前可执行操作；
- 白昼和夜晚使用同一套视觉语言，但显示明确不同的操作重点；
- 六种界面状态具有统一材质、层级、间距和交互反馈；
- 在 1152×648、1280×720、1920×1080 下无越界、无关键控件重叠；
- 图片内不烘焙文字、数字和动态信息；
- 新资源导入失败时，原生 Godot 样式兜底仍可保持功能可用；
- 新界面验收通过后，旧战斗 UI 专用布局与视觉资源被删除，且不误删共享资源。

## 3. 选定技术路线

采用“模块化皮肤 + Godot 原生文字与状态”的实现方式。`gpt-image-2` 分别生成透明 PNG 面板、按钮、卡框、图标、仪表框和弹窗装饰；Godot 负责文字、数值、进度、交互态与响应式布局。

不采用整屏切片或单张大底图，因为它们难以稳定适配多分辨率、按钮状态和动态内容。可拉伸面板使用九宫格，按钮四态保持相同外轮廓与内容安全区，图标保持独立资源。

所有新资源进入独立的 `assets/ui/generated/battle_ui_v2/` 目录，生成源文件与报告放入对应的 `art_source` 新目录。旧资源只在新界面完成验证后删除。

## 4. 视觉系统

### 4.1 材质与色彩

- 面板：深蓝灰或深棕紫的半透明玻璃与旧纸张混合质感；
- 边框：细窄、磨损的旧黄铜，局部带植物根脉雕纹；
- 生命与可用状态：暖金、暖白；
- 战术与敌情信息：冷青；
- 危险、腐化、重伤和首领：克制的暗红；
- 禁用状态：降低亮度与饱和度，不依赖纯灰遮罩；
- 禁止现代科技 HUD、霓虹赛博、过度玻璃拟态、厚重中世纪花纹和高饱和糖果色。

### 4.2 生成约束

- 真实透明 PNG，不使用棋盘格、白底或伪透明背景；
- 图片内禁止文字、字母、数字、费用、倒计时、签名与水印；
- 同组四态按钮轮廓、端帽、雕纹位置和安全区完全一致；
- 面板中心保持安静，装饰集中在可固定的边角和端帽；
- 先生成视觉基准件，确认黄铜、笔触、透明度和边缘质量后再扩展整套资源；
- 项目提供的 API 凭据只在生成进程中注入，不写入仓库、报告或配置文件。

## 5. HUD 布局

### 5.1 常驻锚点

- 左上 `MotherStatusPanel`：母花头像、生命条、生命数值、光脉状态；
- 顶部中央 `PhaseBanner`：当前昼夜阶段及阶段次要信息；
- 右上 `ResourcePanel`：光能、种子、当前夜数；
- 右侧中部 `TacticalInstrument`：圆形战术仪表；
- 底部中央 `PhaseActionTray`：当前阶段的卡牌与操作；
- 右下 `PrimaryActionButton`：当前阶段唯一主操作；
- 左下 `SelectionDetailPanel`：仅在选中有效目标时出现；
- 阶段栏下方 `NotificationBanner`：事件触发后短暂出现并自动退场。

UI 使用视口边缘作为稳定锚点，中央战斗区域保持通透。所有常驻面板避免形成贯穿全屏的厚重框架。

### 5.2 白昼状态

- 阶段栏显示白昼、当前夜数和倒计时；
- 操作托盘显示部署卡、修复和白昼相关操作；
- 战术仪表显示光脉网络；
- 主按钮执行“开始守夜”；
- 隐藏夜间战斗手牌、威胁外圈和太阳爆闪；
- 倒计时进入危险区后，以低频暗红脉冲提示，不遮挡战场。

### 5.3 夜晚状态

- 阶段栏显示夜战、剩余敌人和首领状态；
- 操作托盘原位切换为战斗手牌，并按实际卡数收缩；
- 战术仪表保留网络内圈，叠加八方向威胁外圈与首领标记；
- 主按钮执行“太阳爆闪”，显示真实能量费用；
- 能量不足时按钮禁用，图标与边框降亮，费用使用暗红反馈；
- 隐藏白昼部署、修复和开始守夜操作。

## 6. 弹窗与全屏状态

所有弹窗属于同一“温室园艺档案”体系，使用统一遮罩、黄铜框架、标题区、内容区与操作区。弹窗出现时正确阻断其下方战斗输入。

### 6.1 母花强化

显示三张标本卡：金色生命路线、青色光脉路线、暗红风险路线。卡牌图像只提供框架、图标位和纹章装饰，名称、说明、数值与选择状态由 Godot 绘制。

### 6.2 暂停

使用窄幅园艺记录册面板，背景战场保留可辨识度但降低对比。提供继续、设置和退出等现有功能，不增加新的菜单层级。

### 6.3 胜利

使用暖金晨光、完整母花纹章与修复感较强的黄铜框架，强化“守住一夜”的希望感。结算数据和按钮使用原生控件。

### 6.4 失败

使用冷紫腐化、破损黄铜和枯萎母花纹章，但仍保持文字和操作按钮清晰。失败画面不使用大面积纯黑遮盖。

## 7. 组件与数据边界

现有游戏逻辑继续向 HUD 提供结构化状态。HUD 不直接读取或修改战斗对象，公开信号和调用契约保持兼容，包括部署、修复、开始夜晚、太阳爆闪、战斗卡牌、母花强化与战术仪表相关交互。

界面内部按职责拆分：

- 状态层：生命、阶段、资源；
- 操作层：白昼托盘、夜间手牌、主操作；
- 战术层：光脉网络、威胁方向；
- 临时层：选择详情、通知、资源不足反馈；
- 模态层：强化、暂停、胜利、失败。

HUD 状态机至少覆盖 `day`、`night`、`paused`、`mother_choice`、`victory` 和 `defeat`。模态状态的进入与退出不得破坏底层昼夜状态，关闭模态后恢复此前界面。

## 8. 删除与迁移策略

“删除旧 UI”采用可验证迁移，不先将项目删空：

1. 建立 V2 资源目录、清单和原生兜底样式；
2. 构建新布局并保持旧公开接口兼容；
3. 生成并接入新资源；
4. 完成自动测试与八类截图验收；
5. 查明旧资源的引用关系，只删除战斗 UI 专用且已无引用的文件；
6. 删除旧布局分支、旧资源绑定和兼容期临时代码；
7. 再次执行全量相关测试与资源引用检查。

共享给主菜单、卡组编辑器或其他界面的资源不删除。当前工作区已有的主菜单未提交修改必须保持不变。

## 9. 错误处理与安全

- 新贴图缺失、加载失败或尚未导入时，组件使用可读的 `StyleBoxFlat` 与原生图标占位；
- 缺少动态字段时显示安全默认值，不中断界面构建；
- 空卡组、零敌人、无选中目标等状态不保留空面板；
- 生成结果若存在伪文字、不透明背景、裁切、状态轮廓漂移或低分辨率模糊，必须重新生成或后处理，不进入运行时目录；
- API 地址、密钥及认证信息不得进入源文件、命令输出报告、设计文档或 Git 历史。

## 10. 测试与视觉验收

### 10.1 自动测试

- 公开方法、信号和节点契约保持可用；
- 六种 UI 状态能正确进入、退出和恢复；
- 昼夜只显示当前阶段相关控件；
- 主按钮文字、行为、费用、启用状态与实时数据一致；
- 模态层阻断下方输入，关闭后恢复原状态；
- 通知自动退场，选择详情默认隐藏；
- 三档目标分辨率下关键控件在视口内且无关键重叠；
- 所有 V2 资源路径有效，旧战斗 UI 专用资源最终无引用。

### 10.2 截图验收

至少保存并检查以下状态：

1. 白昼常规部署；
2. 普通夜战；
3. 首领夜战；
4. 资源不足；
5. 母花强化；
6. 暂停；
7. 胜利；
8. 失败。

每张截图检查中央母花可见性、阅读顺序、色彩层级、文字对比、交互态、边缘留白、控件重叠和材质一致性。自动测试通过但视觉验收失败时，不视为完成。

## 11. 完成定义

只有在新模块化资源全部接入、六种状态功能完整、八类截图通过视觉检查、目标分辨率通过布局测试、旧战斗 UI 专用资源和布局已安全删除，并且主菜单等范围外内容未被修改时，本次重做才算完成。
